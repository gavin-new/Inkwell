# Inkwell — 演进路线图

> 主工作区：`E:\TradingPlan\Markdown edit\`  
> EXE 现状：2.96 MB · 启动 ~0.7s · .NET 10 + WebView2 · MIT  
> 当前 UI：双列（编辑 + 预览）

---

## 🎯 产品定位

> **Inkwell 是一个本地优先、可扩展的 Markdown 编辑器。**
> 
> 核心：纯文本文件、离线可用、隐私可控、单文件 EXE。
> 
> 演进方向：**从"单文件编辑器"走向"轻量 IDE / 笔记工具"**，但始终保持单文件 EXE ≤ 5MB、启动 < 1s 的硬指标。

## 🛣️ 演进路线（5 阶段）

### P0：布局框架（基础）
**目标**：实现"可切换的多种布局"基础设施，所有后续 P1-P4 都依赖这个框架。

**子任务**：
- [ ] 把主区拆分为 3 个 slot：`left` / `center` / `right`
- [ ] 每个 slot 可显示/隐藏/可调整宽度
- [ ] 顶栏新增"布局"下拉菜单
- [ ] 预设 4 种布局：单列 / 双列 / 文件树+编辑+预览 / 大纲+编辑+预览
- [ ] 布局选择持久化到 localStorage
- [ ] 响应式：窗口缩小到 < 900px 时自动折叠侧栏

**工作量**：半天（~150 行 HTML/CSS/JS）

**验收**：
- 顶栏"布局 ▾"下拉可切换 4 种布局
- 切换时主区流畅过渡（无闪烁）
- 重新打开 EXE 布局保持

**依赖**：无（基础）

---

### P1：文件树（A 类 3 列）
**目标**：多文件管理 — 适合"项目/书/博客"用户。

**子任务**：
- [ ] 侧栏树形 UI：文件夹 + 文件，支持展开/折叠
- [ ] C# 端新增方法：
  - `listDirectory(path)` — 列目录
  - `watchDirectory(path)` — 监听文件变化
  - `openFileFromTree(path)` — 双击打开
- [ ] 树懒加载（子目录按需展开）
- [ ] 标记"当前打开文件"在树中高亮
- [ ] 文件右键菜单：重命名 / 删除 / 在资源管理器中打开
- [ ] 多标签页：可同时打开多个文件
- [ ] 标签栏拖拽排序

**工作量**：2-3 天

**验收**：
- 打开一个文件夹后左侧显示树
- 双击文件能打开
- 文件被外部修改后树自动刷新
- 多文件切换流畅（< 100ms）

**依赖**：P0

**风险**：
- 目录监听用 `FileSystemWatcher`，事件多需防抖
- 大目录（1000+ 文件）要虚拟滚动

---

### P2：文档大纲（C 类 3 列）
**目标**：长文档导航 — 适合"万字以上"用户。

**子任务**：
- [ ] 解析 H1-H6 生成大纲树
- [ ] 大纲点击跳转到对应行
- [ ] 编辑器滚动时大纲自动高亮当前章节
- [ ] 预览区滚动时大纲同步高亮
- [ ] 大纲可折叠
- [ ] 大纲搜索/过滤

**工作量**：1 天

**验收**：
- 写一个含 20+ 标题的文档，右侧大纲完整显示
- 滚动编辑器时大纲高亮跟随
- 点击大纲项能跳转

**依赖**：P0

---

### P3：历史版本（D 类 3 列）
**目标**：找回"之前写过的内容"。

**子任务**：
- [ ] 自动快照：每 5 分钟或每次保存时存一份
- [ ] 存储在 `localStorage`（轻量）或 `%AppData%` 文件
- [ ] 差异显示（diff）：当前版本 vs 选定快照
- [ ] 一键恢复快照
- [ ] 快照数量上限（保留最近 50 份）
- [ ] 快照列表按时间倒序

**工作量**：1 天

**验收**：
- 编辑一段后等 5 分钟，再等 5 分钟，列表显示 2 个快照
- 选最早快照能 diff 看差异
- 恢复后内容回到那个时刻

**依赖**：P0

**风险**：
- 大文件（> 100KB）频繁快照会占 localStorage 容量
- 改用文件系统存储（`%AppData%\Inkwell\snapshots\`）

---

### P4：AI 助手（B 类 3 列）
**目标**：AI 辅助 — 锦上添花。

**子任务**：
- [ ] 侧栏聊天框
- [ ] 接入选项：
  - **本地**（Ollama）— 离线、免费、需要用户装 Ollama
  - **云端**（Claude / OpenAI）— 联网、需 API key
- [ ] 预置提示词模板：润色 / 翻译 / 解释 / 续写 / 改语气
- [ ] AI 输出可"应用到编辑器"（替换选中文本）
- [ ] 配置页：API key / 模型选择 / 温度

**工作量**：2-3 天

**验收**：
- 选中一段中文，AI 润色后能直接替换
- API key 不明文存储
- 联网失败有友好提示

**依赖**：P0

**风险**：
- API 调用慢/超时
- 内容隐私（云端 AI 会看到用户文本）
- 默认推荐本地 Ollama

## 📅 建议执行顺序

```
P0 布局框架  ──►  P2 大纲  ──►  P1 文件树  ──►  P3 历史  ──►  P4 AI
（0.5 天）     （1 天）    （2-3 天）       （1 天）    （2-3 天）

总工作量：~7-9 天（如果顺序做完）
```

**为什么这个顺序**：
- P0 是基础设施，必须先做
- P2 比 P1 简单且实用，**先做 P2 快速见效**
- P1 复杂（要扫盘、多标签）放后面
- P3 简单（localStorage 就行）放 P1 后面
- P4 最有噱头但最重，放最后

## 🛡️ 硬性指标（每阶段都要保住）

| 指标 | 上限 |
|---|---|
| EXE 体积 | ≤ 5 MB（当前 2.96）|
| 启动时间 | ≤ 1.5s（当前 0.7）|
| 内存占用 | ≤ 300 MB（当前 ~150）|
| 大纲/文件树虚拟滚动 | ≥ 10000 项不卡 |
| 离线优先 | P1-P4 都不破坏离线能力（P4 联网功能可选）|

---

## ❌ 不做的事

- **不做云同步** — 违背"本地优先"
- **不做账号系统** — 违背"纯工具"
- **不做插件系统** — 早期会拖慢开发；等核心稳定再加
- **不做协作编辑** — 需要服务器，超出单文件 EXE 范围
- **不做移动端** — 桌面优先
